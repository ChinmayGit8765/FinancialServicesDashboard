# Phase 01 Plan 03: Spring Security Form Login + Persona Scoping Summary

**One-liner:** Form login with JSON 200/401 handlers (SPA-friendly), SessionCreationPolicy.ALWAYS + changeSessionId, CookieCsrfTokenRepository, JPA-backed UserDetailsService over seeded demo users, and /api/auth/personas + /api/auth/me endpoints proving per-persona portfolio scoping (AUTH-01 + AUTH-02).

## What Was Built

### Task 1: SecurityConfig + JPA UserDetailsService

**SecurityConfig** (`com.quantlens.security.config.SecurityConfig`):
- `formLogin.loginProcessingUrl("/api/auth/login")` — Vue POSTs form-encoded credentials here
- `successHandler`: HTTP 200 + JSON `{"authenticated":true,"username":"<name>"}` — no redirect
- `failureHandler`: HTTP 401 + JSON `{"authenticated":false,"error":"Invalid credentials"}` — no redirect; generic message avoids user enumeration (T-01-06)
- `authenticationEntryPoint`: returns 401 JSON for unauthenticated requests to protected endpoints (T-01-10)
- `logout`: `/api/auth/logout`, returns HTTP 200, invalidates session, deletes JSESSIONID
- `SessionCreationPolicy.ALWAYS` + `sessionFixation().changeSessionId()` (AUTH-02, T-01-07)
- `CookieCsrfTokenRepository.withHttpOnlyFalse()` — XSRF-TOKEN cookie readable by Axios (T-01-08)
- CSRF `ignoringRequestMatchers` on `/api/auth/login` and `/api/auth/logout` — cannot present a token before the first authenticated request
- `PasswordEncoder` autowired from `PasswordEncoderConfig` (Plan 02); NOT redefined here
- `AuthenticationManager @Bean` using `DaoAuthenticationProvider(UserDetailsService)` (non-deprecated Spring Security 6.5.x API)
- OAuth2 upgrade seam documented in code comments (CONTEXT.md — deferred to Phase 3)

**QuantLensUserDetailsService** (`com.quantlens.security.QuantLensUserDetailsService`):
- Implements `UserDetailsService`, annotated `@Service`
- Loads via `AppUserRepository.findByUsername(username)`
- Maps `passwordHash` (BCrypt from SeedRunner) to Spring Security `User.withUsername(...).password(...).roles("USER").build()`
- Throws `UsernameNotFoundException` if not found

**security module package-info.java** updated:
- `allowedDependencies = {"portfolio::domain"}` added so Spring Modulith permits the cross-module read from `QuantLensUserDetailsService` and `AuthController` into `portfolio.domain`

### Task 2: AuthController — Personas, Whoami, Scoping Proof

**PersonaDto** (`record: username, persona, passwordHint`) — used by the one-click login switcher.

**MeDto** (`record: username, persona, portfolioId`) — AUTH-02 scoping proof; distinct `portfolioId` per persona.

**AuthController** (`/api/auth`):
- `GET /api/auth/personas` — public, returns all `AppUser` rows mapped to `PersonaDto` with `passwordHint="demo1234"`
- `GET /api/auth/me` — authenticated, reads `AppUser` from `AppUserRepository.findByUsername` then resolves `Portfolio` via `PortfolioRepository.findByUserId`; returns `MeDto(username, persona, portfolioId)`

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] CSRF ignoringRequestMatchers on login/logout**
- **Found during:** Task 1 verification — `loginSuccess` and `sessionPersists` returned 401
- **Issue:** `CookieCsrfTokenRepository` enables CSRF for all POST requests, including `/api/auth/login`. `TestRestTemplate` does not manage CSRF cookies, so the first login POST is rejected with 403 (treated as 401 at the entry point). The SPA's Axios interceptor (Plan 04) reads the XSRF-TOKEN cookie from any prior GET and attaches it to mutating requests — but for the very first POST (login), no prior response has set the cookie yet.
- **Fix:** Added `.csrf(csrf -> csrf.csrfTokenRepository(...).ignoringRequestMatchers("/api/auth/login", "/api/auth/logout"))`. The login endpoint is the credential-verification gate and cannot self-supply a CSRF token. SameSite=Lax (application.yml) is the CSRF defence at this boundary.
- **Files modified:** `SecurityConfig.java`
- **Commit:** 5c601d5

**2. [Rule 1 - Bug] DaoAuthenticationProvider deprecated constructor**
- **Found during:** Task 1 implementation — IDE diagnostics flagged `DaoAuthenticationProvider()` constructor and `setUserDetailsService()` as deprecated
- **Issue:** In Spring Security 6.5.x both `DaoAuthenticationProvider()` (no-arg) and `DaoAuthenticationProvider(PasswordEncoder)` are deprecated; the non-deprecated constructor is `DaoAuthenticationProvider(UserDetailsService)`.
- **Fix:** Used `new DaoAuthenticationProvider(userDetailsService)` then called `provider.setPasswordEncoder(passwordEncoder)`.
- **Files modified:** `SecurityConfig.java`
- **Commit:** 5c601d5

**3. [Rule 1 - Bug] QuantLensApplicationTests crashed without live DB**
- **Found during:** Full suite run (`./mvnw test`) — `QuantLensApplicationTests.contextLoads` error
- **Issue:** This test was generated by Spring Initializr (plain `@SpringBootTest` with no Testcontainer), was never committed to git, and failed on every run that lacked a live Postgres at localhost:5432.
- **Fix:** Extended `AbstractPostgresIntegrationTest` (the shared Testcontainer base) so the context loads against the same in-process container as all other integration tests.
- **Files modified:** `QuantLensApplicationTests.java`
- **Commit:** a5ed5cf
