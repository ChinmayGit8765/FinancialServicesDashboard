<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → frontend (nginx) → backend | SPA traffic proxied to the API; session + CSRF cookies cross here |
| docker compose env → containers | Dev DB credentials injected as env vars |
| dev host → MCP servers | npx-launched stdio MCP processes connect to the local DB |
| npm registry → frontend build | Third-party packages pulled at build time (supply chain) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-11 | Information disclosure | DB credentials in docker-compose.yml | accept | Dev-only credentials (quantlens/quantlens_dev), clearly documented as non-secret in README; no real secret committed; prod uses externalized env/.env (documented) |
| T-01-12 | Tampering | Postgres data corruption on Windows | mitigate | Named volume postgres_data (never a bind mount) per RESEARCH Anti-Patterns |
| T-01-13 | Denial of service | Backend starts before DB ready → crash loop | mitigate | db healthcheck + backend depends_on condition: service_healthy + start_period 20s (RESEARCH Pitfall 2) |
| T-01-14 | Spoofing | CSRF token round-trip in the browser | mitigate | Axios reads XSRF-TOKEN cookie and sends X-XSRF-TOKEN; nginx forwards cookies; SameSite=Lax |
| T-01-SC | Tampering | npm package supply chain (all [ASSUMED]) + deprecated Postgres MCP | mitigate | Blocking-human legitimacy checkpoint (Task 0) before first install; pinned audited versions; @modelcontextprotocol/server-postgres (deprecated, SQLi) explicitly forbidden — use @henkey/postgres-mcp-server or user-scoped fallback |
</threat_model>
