## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → /api/portfolio/{holdings,allocation} | Untrusted request; only the session principal is a trusted identity source |
| controller → service → Postgres | Internal; parameterized JPQL; entities never serialized |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation of Privilege (IDOR) | PortfolioController.resolvePortfolioId | mitigate | Portfolio ID derived ONLY from Authentication.getName() → AppUser → Portfolio. No @RequestParam/@PathVariable accepts a portfolio or user identifier. Verified by getHoldings_unauthenticated_returns401 and by the principal-scoped holdings test returning alice's 5 holdings only. |
| T-02-02 | Information Disclosure | service → JSON | mitigate | Endpoints return HoldingDto/AllocationSliceDto records, never JPA entities — no lazy-load leakage of AppUser/passwordHash. All loads inside @Transactional(readOnly=true). |
| T-02-04 | Tampering | BigDecimal divide without rounding | mitigate | Every divide() specifies (scale, RoundingMode.HALF_UP); allocation last-slice residual absorption guarantees weights sum to exactly 1.000000 — prevents 99.9999%/100.0001% display artifacts. |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages this phase (RESEARCH.md audit: none). No legitimacy checkpoint required. |
</threat_model>
