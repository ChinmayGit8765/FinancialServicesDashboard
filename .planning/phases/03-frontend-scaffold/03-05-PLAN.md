<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| persona switch → POST /api/auth/login | State-changing session re-auth from the SPA |
| dashboard mount → /api/portfolio/* | Authenticated reads on view entry |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-11 | Tampering (CSRF) | persona switch POST /auth/login | accept | /api/auth/login is intentionally CSRF-exempt (Phase 1 ignoringRequestMatchers); SameSite=Lax is the CSRF defence at the login boundary (Phase 1 decision). No new surface. |
| T-03-12 | Spoofing / data leak | stale persona data after rapid switch | mitigate | switchPersona debounces with a `switching` flag; the store's refreshVersion guard discards stale batch results so Bob never shows Alice's data (RESEARCH.md Pattern 4/5, Pitfall 6). Verified in the human checkpoint (rapid-click step). |
| T-03-13 | Tampering (XSS) | persona/username rendering in TopBar/LoginView | mitigate | All persona/username strings rendered via Vue interpolation; no v-html. |
| T-03-14 | Information disclosure | logout | mitigate | logout() clears local store state and invalidates the server session; the 401 interceptor (Plan 02) covers any subsequent stale request. |
</threat_model>
