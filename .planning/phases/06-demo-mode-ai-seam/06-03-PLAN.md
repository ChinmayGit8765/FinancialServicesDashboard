ExplainPositionService.explain(Long portfolioId, String ticker) → ExplainResponseDto:
- Resolve the holding: call portfolioService.getHoldings(portfolioId), filter by ticker. If the ticker is not in the principal's holdings, throw ResponseStatusException(HttpStatus.NOT_FOUND) — this is the IDOR-safe guard (a user cannot explain a position they do not hold). Do NOT trust the ticker blindly for the seed lookup.
- Build a metrics summary string from the matched HoldingDto (ticker, sector, quantity, currentMarketValue, portfolioWeight, unrealizedPnlPct) for the LIVE prompt only.
- Call strategy.forSession(keyHolder).prompt() with a system prompt (concise financial-analyst persona) and a user prompt template referencing ticker + metrics; set advisor params via `.advisors(spec -> spec.param("AI_SEED_TYPE","EXPLAIN_POSITION").param("AI_SEED_SUBJECT", ticker))`; `.call().content()` returns the String. In demo mode the DemoModeAdvisor short-circuits and returns the seeded EXPLAIN_POSITION fixture for that ticker; in live mode the real model generates a structurally-similar narrative (Pitfall 12).
- Wrap the content in new ExplainResponseDto(content). Wrap the ChatClient call in a try/catch that, on any provider exception, throws a generic ResponseStatusException(HttpStatus.BAD_GATEWAY) WITHOUT including exception.getMessage() (Pitfall 5 — never echo a provider error that could carry the key). @Transactional(readOnly=true). NOTE: the NOT_FOUND guard must run BEFORE the ChatClient call (validate the ticker against holdings first), and must NOT be swallowed by the provider try/catch.

CommentaryService.commentary(Long portfolioId) → CommentaryDto:
- Derive the persona key (GROWTH|INCOME|BALANCED) from the portfolio. Determine the mapping from the seeded portfolios — read 06-01/06-02 SUMMARY for how persona maps to portfolioId/username, or infer from holdings composition. Document the chosen mapping in SUMMARY.
- Call strategy.forSession(keyHolder).prompt() with a commentary system+user prompt; set `.advisors(spec -> spec.param("AI_SEED_TYPE","DAILY_COMMENTARY").param("AI_SEED_SUBJECT", personaKey))`; `.call().content()` returns the stored content string (demo) or a live generation.
- Parse the content string into CommentaryDto(headline, body, bulletPoints) using the EXACT storage convention recorded in 06-02-SUMMARY (e.g. first line = headline, blank-line-separated body, "- "-prefixed lines = bullets). Keep the parser tolerant: if the content does not match the convention (e.g. a free-form live response), fall back to headline = first sentence, body = remainder, bulletPoints = empty. Same try/catch generic-error handling as explain. @Transactional(readOnly=true).
