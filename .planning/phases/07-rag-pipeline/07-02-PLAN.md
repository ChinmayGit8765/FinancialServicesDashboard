## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → POST /api/ai/chat | Untrusted user question enters the AI layer |
| seeded 10-K chunk text → LLM prompt (live) | Retrieved document content is untrusted text in the prompt context |
| session key → provider | Session-only key must never reach client/logs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-LEAK | Information Disclosure | ChatService 502 path + POST /api/ai/chat | mitigate | Generic 502 message only; KeyLeakageIntegrationTest (extended in 07-01) stays green over /api/ai/chat; provider error message never echoed |
| T-07-PI | Tampering | retrieved 10-K chunk context (live) | mitigate | System prompt instructs the model to treat [FILING_CONTEXT] as data only and ignore embedded instructions (set in 07-01 ChatService prompt / QA promptTemplate); demo answers are authored seed so injection can't reach a live model; seeded corpus is author-controlled (no user uploads in v1) |
| T-07-IDOR | Information Disclosure | conversation memory | mitigate | conversationId = HttpSession.getId(); MessageWindowChatMemory per-conversationId; ChatMemoryIntegrationTest proves turns are scoped to one conversation |
| T-07-SEED | Tampering | rag-v1 / ai-v3 idempotent seed | mitigate | seed_log guards write the completion marker LAST inside @Transactional so a mid-seed crash rolls back; idempotency test asserts exactly-once |
</threat_model>
