## Implementation Decisions

### Vector store + seeded corpus
- Add `spring-ai-starter-vector-store-pgvector` (BOM 1.1.6). The Phase-1 `vector_store` table (dimension 1536, HNSW, `initialize-schema=false` — Flyway owns it) is the store. Configure Spring AI pgvector to USE the existing table without re-creating it (initialize-schema stays false).
- Seed a small corpus: 3–5 short, table-light SEC 10-K excerpts (e.g. AAPL, MSFT, NVDA, JPM, XOM — tickers already in the seeded universe), chunked into a handful of passages each. Store the chunks (+ metadata: ticker, section, source) and their embeddings in `vector_store`, seeded idempotently at startup (extend the seeder; seed_log key e.g. `rag-v1`).

### Zero-key demo embeddings (the crux)
- The demo MUST run with NO API key and NO network — so document embeddings cannot be generated by calling a real embedding API at build/startup time in this autonomous build.
- **Approach (research to confirm the cleanest):** generate the seeded document embeddings with a DETERMINISTIC, no-key local method so vector similarity search is structurally real on a cold start. Options for research to evaluate: (a) a deterministic local embedding (e.g. a hashing/bag-of-words projection into 1536-dim, or a small local model) committed/computed at seed time with no key; (b) pre-computed embeddings committed as seed data. Bias: keep it dependency-free (no Ollama requirement) and reproducible. The embeddings need only be internally consistent for demo retrieval — semantic perfection is not required for the seeded Q&A.
- Document the chosen demo-embedding strategy + its limitation (demo embeddings are illustrative; with a live key the same retrieval path uses the real embedding model) in MODELS.md or a RAG doc.

### Demo vs live Q&A
- **Demo mode (no key):** the `DemoModeAdvisor` (Phase 6) short-circuits chat/RAG questions with AUTHORED answers for a curated set of demo questions, each citing the actual seeded 10-K chunks (real source citations). Retrieval over the seeded (deterministic) embeddings runs to surface the cited chunks where practical; the ANSWER text is seeded. No provider/network call.
- **Live mode (key present):** the chain runs `QuestionAnswerAdvisor` (retrieval over pgvector using the real embedding model to embed the query) → real LLM generates the answer grounded in retrieved chunks, with citations. Conversation memory via `MessageChatMemoryAdvisor` (in-memory per session, conversation id = session). Same retrieval path; only generation differs.
- Advisor order: DemoModeAdvisor (HIGHEST_PRECEDENCE, short-circuits demo) → QuestionAnswerAdvisor (RAG) → MessageChatMemoryAdvisor → model. In demo the first short-circuits before the others.

### Surface (REST + frontend)
- `POST /api/ai/chat` (body: { message, conversationId? }) → { answer, citations[] } — principal-scoped, session conversation memory. Goes through ChatClient + the advisor chain (seeded in demo, live with key).
- Frontend: a Q&A chat panel (message list + input) filling the Phase-3 "AI Q&A — Phase 7" slot (the StructuredOutputChart stub from Phase 6 may move or coexist — keep the structured stub; add the chat). Pinia ai store gets chat state (messages, loading) + sendMessage action; renders citations. Reuse the demo/live mode badge.

### Testing
- Demo-mode integration: /api/ai/chat returns seeded answer + citations with NO key and NO provider call (reuse the counting-CallAdvisor no-network proof pattern). Retrieval test: seeded chunks are searchable in pgvector (vector store populated; a similarity query returns expected chunks). Memory test: multi-turn conversation retains context (demo seeded answers may be turn-aware for a curated flow). Key-leakage gate stays green. Frontend: chat panel component test (send → message appended, citations rendered, loading state). Use Testcontainers pgvector. No live network in tests.

### Claude's Discretion
- Exact demo-embedding method, corpus selection + chunk sizes, conversationId scheme, citation shape, and whether the chat replaces or coexists with the structured-output stub in the slot — at Claude's discretion within the above. Research to confirm Spring AI 1.1.6 QuestionAnswerAdvisor + pgvector wiring against the existing table, MessageChatMemoryAdvisor, and the zero-key demo-embedding approach.
