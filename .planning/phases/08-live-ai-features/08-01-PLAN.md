ChatClientStrategy (current — extend forSession to register tools):
```java
@Service
public class ChatClientStrategy {
    private final AnthropicChatModel baseAnthropicModel;
    private final OpenAiChatModel    baseOpenAiModel;
    private final List<CallAdvisor>  advisors;   // sorted by Ordered
    public ChatClient forSession(LlmKeySessionHolder keyHolder) {
        ChatModel model = buildModel(keyHolder);
        return ChatClient.builder(model)
                .defaultAdvisors(advisors.toArray(new CallAdvisor[0]))
                .build();
    }
    // buildModel: !hasKey -> baseAnthropicModel; "anthropic" -> buildAnthropicModel; "openai" -> buildOpenAiModel
}
```

LlmKeySessionHolder methods: `hasKey()`, `getProvider()` ("anthropic"|"openai"), `getApiKey()`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ChatModel → @Tool invocation | The LLM decides to call `getStockQuote(ticker)` server-side; ticker text originates from the user message |
| FinnhubQuoteClient → finnhub.io | Outbound HTTP carrying the Finnhub market-data credential in the URL query string |
| Application config → FinnhubQuoteClient | `FINNHUB_API_KEY` env var (separate from the LLM key; never session-scoped) |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-08-LEAK-FH | Information Disclosure | FinnhubQuoteClient catch block | mitigate | Log ONLY the ticker; NEVER `e.getMessage()`/`e.toString()`/cause — Java HttpClient embeds `?token=...` in the exception message (08-RESEARCH Pitfall 3). Verified by grep + KeyLeakage gate in 08-03 |

| T-08-SC | Tampering | npm/pip/cargo installs | accept | No new packages added (Java HttpClient is JDK built-in; Spring AI BOM-governed). 08-RESEARCH Package Legitimacy Audit confirms zero new installs |
